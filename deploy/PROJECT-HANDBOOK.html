1. The project in 30 seconds

Memorise this answer: “I built a voice-first RAG receptionist for a fictional GP surgery. Clinic Markdown documents are split by semantic headings, embedded locally with BGE-small, and stored in Qdrant. For each question, the API retrieves the top five passages above a relevance threshold, inserts them into a safety-focused prompt, and calls Gemini with DeepSeek available as a configurable fallback. Text sessions are persisted in Supabase and return citations. For live voice, ElevenLabs handles streaming audio, speech recognition, turn detection, interruption and TTS, while calling my OpenAI-compatible SSE endpoint as its custom LLM. The Next.js frontend proxies secrets server-side, and the stack runs on OCI behind Caddy with HTTPS while the UI is on Vercel.”

The business problem

Patients repeatedly ask factual questions—opening hours, prescription lead times, appointment rules, registration and out-of-hours care. A normal LLM may confidently invent an answer. This system constrains answers to a small, inspectable knowledge base and lets a visitor click the cited source.

The central design principle

Voice is an interface; RAG is the knowledge system. Text chat, recorded voice and realtime voice all reuse ClinicAssistant.answer(). This prevents three channels from developing three different truth sources.

5.1 Source format

Ten fictional Markdown files contain approximately 78 indexed passages. Front matter supplies title, category and last_reviewed. A ## heading represents one answerable fact. See knowledge_base/.

---
title: Opening hours and contact
category: access
last_reviewed: 2026-11-01
---
## Opening hours
On Tuesdays the surgery offers extended hours and closes at 20:00.

5.2 Chunking — app/rag/loaders.py

  1. Files are sorted for deterministic behaviour; README.md is excluded.
  2. Simple front matter is parsed without a YAML dependency.
  3. MarkdownHeaderTextSplitter splits on level-two headings.
  4. Any unusually long section is split on paragraph boundaries at roughly 1,200 characters.
  5. The stored text is prefixed with Document title — Section. The heading therefore contributes meaning to the vector.
  6. Metadata travels beside every vector: source, title, section, category, review date and position.
Why semantic headings rather than fixed 500-token windows? Each clinic section is already a self-contained answer. Arbitrary windows may split a rule from its exception or mix unrelated facts.

5.3 Stable IDs and idempotency

document_id() computes UUIDv5 from source#section#position. Re-running ingestion produces the same IDs. Before inserting one source, all existing points for that source are deleted; this also removes chunks whose headings were deleted. See app/rag/ingest.py.

5.4 Embeddings — app/rag/embeddings.py

BAAI/bge-small-en-v1.5 converts text into a 384-dimensional dense vector. Semantically similar text should point in a similar direction. FastEmbed uses an efficient local runtime; the model is about 50 MB and is downloaded once.

Qdrant uses cosine similarity:

cosine(q, d) = (q · d) / (||q|| × ||d||)

Higher score ⇒ query and document vectors point in a more similar direction.

5.5 Qdrant — app/rag/vector_store.py

  • The collection is created with 384 dimensions and cosine distance.
  • A dimension mismatch fails loudly and asks for --rebuild; mixing embedding dimensions is invalid.
  • Keyword payload indexes on metadata.category and metadata.source make filtered operations cheaper.
  • LangChain stores page content and metadata using its standard Qdrant payload shape.
  • Ingestion batches at 64 chunks.

6.1 Retrieval — app/rag/retriever.py

The query is embedded with the same model as the documents. Qdrant returns up to RETRIEVAL_TOP_K=5 passages whose similarity reaches RETRIEVAL_MIN_SCORE=0.5. Optional category filtering is supported.

RetrievedChunk is a typed application object containing the text, score and citation metadata. format_context() numbers passages before inserting them into the prompt.

6.2 Grounding gate — app/agents/clinic_assistant.py

If no passage reaches the threshold, the model is not called. The system returns a fixed “I do not have that information” response and grounded=false. This:

  • reduces hallucination risk;
  • saves model cost and latency;
  • makes the result deterministic;
  • signals the UI that no source supported the answer.

6.3 Generation chain

PROMPT | llm_with_fallbacks | StrOutputParser()

The prompt receives three values: retrieved context, the current question and recent conversation history. StrOutputParser extracts plain answer text. The returned Answer also carries source chunks and grounded status.

6.4 LLM provider strategy — app/services/llm.py

LLM_ORDER controls runtime ordering without a deployment. Missing keys are skipped. The code default is Gemini then DeepSeek; configured providers omitted from the list are appended. LangChain’s with_fallbacks() retries the same chain through the next model if the primary fails.

  • Gemini uses ChatGoogleGenerativeAI.
  • DeepSeek uses ChatOpenAI with base_url=https://api.deepseek.com, because its protocol is OpenAI-compatible.
  • Timeout is 45 seconds and provider clients allow two retries.
  • Temperature is low (0.2) where the model accepts it, favouring factual consistency.
Known ranking weakness: dense retrieval can rank “When the surgery is closed” above “Opening hours” for a closing-time question because wording similarity is not exact factual reasoning. The correct passage remains in top five. The planned fix is hybrid BM25 + dense retrieval fused with Reciprocal Rank Fusion.

7. Prompting and safety

The policy is centralised in app/services/prompts.py, making it reviewable as a business rule rather than hiding it inside route code.

RuleReason
Emergency symptoms → call 999 immediatelySafety instruction must outrank normal grounding behaviour.
Use only supplied clinic contextStops invented hours, prices, policies and staff names.
No diagnosis or medical adviceThe assistant is reception, not a clinician.
Closed + urgent → NHS 111Explicit out-of-hours escalation.
Two or three plain sentences; no MarkdownThe same answer may be spoken. TTS should not read formatting aloud.
Ask a clarifying question when unclearBetter than guessing intent.
Honest limitation: prompting and retrieval reduce risk; they do not make an LLM clinically safe. This is a fictional demo, not a medical device. A production healthcare system would require clinical governance, evaluation, audit, privacy controls, incident response and human escalation.

Shared turn setup — app/api/turns.py

begin_turn() is shared by text chat and recorded voice. It creates a new session or validates an existing one, rejects unknown sessions with 404 and ended sessions with 409, loads the latest 10 messages, then stores the new user message.

The user message is stored before generation. If the model fails, a reviewer still knows what the user asked. The assistant answer is stored after generation.

Supabase schema — db/migrations/0001_baseline.sql

  • sessions: UUID, active/ended status, timestamps.
  • messages: session foreign key, role, content, timestamp.
  • appointments: future booking-tool table; currently unused.
  • RLS is enabled with no public policies. Only the backend’s service key bypasses RLS.

Repository functions in app/database/repositories.py take an explicit client, enabling lightweight fakes in tests. Column lists are explicit to avoid silently exposing future database fields.

9. Realtime voice: what ElevenLabs does

Essential answer: “I did not build a low-level audio server. ElevenLabs Agents owns the realtime speech loop. My browser joins using a short-lived signed URL; ElevenLabs transcribes speech, detects when the user finishes, sends the transcript/history to my OpenAI-compatible RAG endpoint, turns my streamed text into speech, and handles interruptions. My system retains control of knowledge, safety and cost gates.”

9.1 Full realtime sequence

BrowserRequests microphone first, then calls Next.js /api/voice-session.
FastAPIChecks daily allowance and asks ElevenLabs for a signed URL using the private API key.
Browser@elevenlabs/react opens a WebSocket using only the signed URL.
ElevenLabsStreams mic audio → ASR → turn model. It decides the user finished speaking.
ElevenLabsSends OpenAI-style messages to POST /v1/chat/completions with a workspace secret.
Our APIImmediately streams “One moment…”; runs Qdrant + LLM; streams the grounded answer and [DONE].
ElevenLabsTTS speaks chunks; interruption/barge-in stops or adjusts playback; transcript events return to React.

9.2 Signed URLs — app/services/voice.py and app/api/routes/voice_session.py

The browser must never receive ELEVENLABS_API_KEY. FastAPI calls:

GET https://api.elevenlabs.io/v1/convai/conversation/get-signed-url
    ?agent_id=agent_...
Header: xi-api-key: [server secret]

It returns a short-lived, agent-scoped URL. The route only decrements the budget after ElevenLabs successfully creates it, so failed handshakes do not consume the local allowance.

9.3 What an ElevenLabs Agent contains

  • ASR: automatic speech recognition converts audio into user transcript.
  • Turn model/VAD: voice activity and learned turn-taking decide when to wait, respond or allow interruption.
  • LLM: configured as our custom endpoint rather than ElevenLabs’ built-in model.
  • TTS: the selected voice/model synthesises our text incrementally.
  • Conversation state: ElevenLabs sends prior user/assistant messages on subsequent custom-LLM requests.
  • Call history: transcript, timing and errors are visible in the ElevenLabs platform.

9.4 Custom LLM protocol — app/api/routes/llm.py

ElevenLabs expects an OpenAI Chat Completions-compatible endpoint at /v1/chat/completions with Server-Sent Events:

data: {"object":"chat.completion.chunk",
       "choices":[{"delta":{"content":"One moment... "},"finish_reason":null}]}

data: {"choices":[{"delta":{"content":"We close at 20:00 on Tuesdays."}}]}

data: {"choices":[{"delta":{},"finish_reason":"stop"}]}

data: [DONE]

The route extracts the last user message as the current question, converts earlier user/assistant messages to RAG history, ignores ElevenLabs’ system/tool messages, and caps history to ten.

9.5 Why the buffer phrase exists

The RAG chain is currently non-streaming: local query embedding + Qdrant + Gemini typically takes a few seconds. Silence feels broken in a voice call. The sync generator yields a short phrase before calling assistant.answer(), allowing ElevenLabs to begin TTS while the RAG work continues. Once ready, the complete answer is emitted as a second chunk.

Latency trade-off: a buffer phrase improves perceived latency but can become repetitive. A better future design streams model tokens directly, uses ElevenLabs soft-timeout fillers, caches safe frequent answers, and measures ASR end-of-turn → first audio byte.

9.6 React call lifecycle — web/components/CallPanel.tsx

  • ConversationProvider owns SDK state; useConversation exposes connection status and controls.
  • Microphone permission is requested before a signed URL, preventing a blocked mic from spending a call.
  • onMessage maps ElevenLabs user/ai transcript events into the existing TurnList.
  • Status derives from isListening/isSpeaking; mute calls setMuted().
  • A 90-second browser deadline calls endSession().
  • Unmount cleanup ends a live session, preventing a hidden paid call and open microphone.
  • The component is dynamically imported in Workspace.tsx, so text-only visitors do not download the voice SDK initially.

9.7 Cost protection — app/services/voice_budget.py

A mutex-protected in-memory counter limits signed URLs per UTC day. It is correct for one Uvicorn worker, resets at midnight and also resets on restart. It is intentionally simple for a demo. The UI timer is not a security boundary; the ElevenLabs agent’s max-duration setting is the provider-side backstop.

For multiple workers/instances, move the counter to Redis or Postgres using an atomic increment with expiry.

11. Frontend and explainability UX

Backend-for-Frontend pattern

The browser only calls Next.js /api/*. Server route handlers use web/lib/backend.ts to attach BACKEND_API_KEY and forward to OCI. Benefits:

  • the key never enters the JavaScript bundle;
  • requests are same-origin, simplifying CORS;
  • backend location can change through API_BASE_URL without rebuilding client code patterns.

Single-screen verification loop

web/components/Workspace.tsx loads documents and coordinates the active source. Text citations call openSource(source, section), switch the mobile tab to Documents, and pass a jump target to DocumentViewer. The viewer finds data-section, scrolls smoothly and flashes the source for 2.4 seconds.

app/rag/catalog.py is important: it rebuilds full human-readable sections from the same loader output used for ingestion. The display strips only the artificial title prefix. Thus the demo does not show one document while indexing another.

Responsive strategy

Large screens show navigation, document reader and assistant side by side. Below lg, documents and assistant become tabs. State lives in the parent so clicking a citation can move between panes.

Why synchronous FastAPI routes?

Supabase, FastEmbed, Qdrant’s used methods, HTTPX calls and LangChain invocation are blocking. Routes such as /chat are declared with normal def, so FastAPI executes them in a thread pool. Writing async def while calling blocking work would freeze the event loop.

Latency decomposition

Voice turn latency ≈ end-of-turn detection
                   + query embedding
                   + Qdrant network search
                   + LLM time-to-answer
                   + TTS first-audio latency
                   + network/playback buffering

The observed logs prove where time is spent: signed URL succeeds, ElevenLabs calls our endpoint, Qdrant returns, Gemini generates, then ElevenLabs synthesises. The current largest controllable component is non-streaming LLM generation.

13. Security model

  • Constant-time comparisons: secrets.compare_digest() reduces timing leakage for API secrets.
  • Separate credentials: browser-facing proxy key and ElevenLabs custom-LLM secret have different scopes.
  • Signed voice URL: no ElevenLabs master key in the browser.
  • Server-only environment variables: Vercel variables are not prefixed NEXT_PUBLIC_.
  • RLS: Supabase anonymous clients cannot read data; service role stays backend-only.
  • Least exposure: Uvicorn binds localhost; only Caddy accepts internet traffic.
  • TLS/security headers: Caddy manages certificates, HSTS, nosniff, referrer policy and removes Server header.
  • Input validation: Pydantic request limits plus audio media type/size checks.
  • systemd hardening: dedicated user, no new privileges, private temp, read-only home/system except model cache.
  • No secret logging: failed agent auth logs header names, never values.
Production gaps: shared API key is not user authentication; in-memory rate limiting is not distributed; realtime transcripts are held by ElevenLabs; no PII redaction/audit retention policy is implemented. These are acceptable only because this is a fictional demo.

Why these choices?

  • OCI: inexpensive/free VM with full control and a stable backend hostname.
  • No Docker: native uv + systemd reduces layers for a single Python service and was a stated constraint.
  • uv: fast deterministic installs from uv.lock.
  • systemd: starts at boot, restarts on failure and provides journalctl logs.
  • Caddy: automatic certificate issue/renewal and simple reverse proxy configuration.
  • One worker: fits memory and keeps the in-memory call budget coherent. Scale-out needs shared rate-limit state.
  • Vercel: natural deployment platform for Next.js and server route handlers.

FastEmbed cache deployment lesson

PrivateTmp=true gives the service a private temporary directory. FastEmbed’s default cache there would redownload or become inaccessible. The unit explicitly sets FASTEMBED_CACHE_PATH=/home/ubuntu/.cache/fastembed, grants that path through ReadWritePaths, and requires the directory to exist. Missing it causes systemd 226/NAMESPACE.

15. Testing and observability

Testing strategy — tests/

The suite contains 82 tests and avoids paid/network calls:

  • Fake embeddings: deterministic vectors make ranking assertions stable.
  • In-memory Qdrant: exercises real collection/filter/search semantics without cloud access.
  • Fake Supabase: a minimal query-builder fake records sessions/messages.
  • Fake assistant and voice: HTTP tests verify wiring and error handling rather than provider availability.
  • HTTPX monkeypatching: pins exact ElevenLabs request shapes and prevents key leakage.
  • Contract tests: SSE ordering, authentication, [DONE], history extraction and fallback speech.
  • Behaviour tests: grounding skips the model; history is capped; source deletion is scoped; documents match chunk count.

Debugging rule

Separate retrieval from generation. Call /search. If the right passage is missing, fix content/chunking/embeddings/ranking. If it is present but the answer is wrong, inspect prompt/model behaviour. This avoids blindly changing the LLM for a retrieval problem.

17. Interview questions and strong answers

RAG and data

Why RAG instead of fine-tuning?
Clinic facts change and must be inspectable. RAG updates by editing/re-indexing documents, returns citations, and separates factual knowledge from model behaviour. Fine-tuning is better for style/behaviour than frequently changing factual truth.

Why Qdrant?
It provides managed vector search, cosine similarity, metadata payloads/filters and a clean LangChain adapter. It also supports local in-memory testing.

Why local embeddings?
No per-query embedding cost or extra external dependency, deterministic dimensions, and a small English corpus fits BGE-small. The trade-off is model memory/startup and weaker ranking than larger models.

How do you prevent hallucinations?
Context-only prompt, score threshold, no-context grounding gate that skips the LLM, short factual output, citations and emergency/no-medical-advice rules. I would not claim hallucinations are eliminated.

Why top five?
It balances recall and prompt noise for a 78-chunk corpus. The number is configurable and should ultimately be chosen from evaluation results, not intuition.

What happens when documents change?
Ingestion deletes all points for that source and re-adds current chunks with stable UUIDv5 IDs. Removed sections disappear. A dimension/model change requires collection rebuild.

Backend and system design

Why FastAPI?
Typed validation, dependency injection, sync thread-pool handling, automatic OpenAPI and strong Python AI-library support.

Why Supabase plus Qdrant?
They solve different data models: relational conversation state and constraints versus high-dimensional nearest-neighbour search. Forcing both into one store would weaken one side; pgvector would be a reasonable simplification at this scale.

Why sync route functions?
The current dependencies are blocking. FastAPI runs sync routes in a worker thread; pretending they are async would block the event loop. A future async stack would require async clients end to end.

How does failover work?
Provider order is environment-driven, missing keys are skipped, and LangChain with_fallbacks() invokes the next chat model when the primary raises an error.

Voice

What exactly does ElevenLabs do?
It maintains the realtime WebSocket, ASR, turn-taking/VAD, interruption handling, transcript events and TTS. It calls my API for intelligence through the OpenAI-compatible custom LLM contract.

Why a signed URL?
It lets the browser open one short-lived agent session without exposing the account-level ElevenLabs API key.

What is SSE doing if audio uses WebSockets?
They are different legs. Browser audio uses a WebSocket to ElevenLabs. ElevenLabs uses HTTP SSE to receive incrementally speakable text from my custom LLM endpoint.

Why is there latency?
Turn detection waits for end of speech, then query embedding, remote vector search, non-streaming LLM generation and TTS each add time. The immediate buffer phrase masks part of this; token streaming and measurement are the next improvements.

How is barge-in implemented?
ElevenLabs’ turn-taking/audio layer handles it, not the FastAPI code. The React SDK reports listening/speaking state while the agent platform interrupts synthesis when configured.

What is the difference between the two voice routes?
/voice/turn uploads a complete recording and explicitly performs STT → RAG → TTS. Realtime voice issues a signed agent session; ElevenLabs owns the continuous speech loop and calls /v1/chat/completions for every turn.

Security, scaling and operations

How are secrets protected?
Browser requests go through Next.js server routes; provider and database keys stay server-side. Realtime uses a signed URL. The custom LLM has a separate secret, compared in constant time.

What breaks if you add more Uvicorn workers?
Each worker gets its own in-memory call counter and cached model/client objects, increasing memory and making quotas inconsistent. I would move quota state to Redis/Postgres before scaling horizontally.

How would you make it production healthcare-ready?
Do not start with model changes: add governance, DPIA/consent, data minimisation, retention/deletion, encryption/key rotation, user auth/RBAC, audit trails, clinical safety review, evaluations, human escalation, incident response, SLAs and provider agreements.
